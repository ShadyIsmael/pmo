# NEXUS React/Vite parity gate

This document records the migration gate for `apps/web-react`. It is intentionally kept
next to the repository so a production cutover cannot be mistaken for a route-only port.

Shared visual rule: semantic status text keeps its semantic foreground color and uses no
tinted status background. Apply this consistently to shared status badges in both apps.

## Gate rule

The Next.js application remains the production canonical application until every active
surface below is either parity-complete or explicitly accepted as deferred by product,
and manual UAT plus the final merge/cutover approval are complete.

## Current audit

### Source route inventory

The source audit enumerated 91 `page.tsx` routes under `apps/web/src/app` and parsed the
React `<Route>` tree in `apps/web-react/src/routes/AppRoutes.tsx`. All Next page paths map to
a React route, redirect, or scoped wildcard. The only paths resolved by a wildcard are the
four report subsections (`custom`, `executive`, `portfolio`, and `scheduled`), handled by the
section-aware report page. This is route coverage evidence only; it does not establish
component depth, API behavior, permission parity, or visual parity. A focused test now guards
against future Next page routes being left without a React route.
