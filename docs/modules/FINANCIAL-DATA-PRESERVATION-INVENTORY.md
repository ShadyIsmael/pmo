## 1. Scope and evidence boundary

This is a read-only inventory of persisted financial record types and their known consumers based on the checked-out source and the current-state audit. It is intended to guide preservation and later reconciliation. It does not describe actual Development database contents.

The repository is on branch `main` with extensive concurrent uncommitted work. Finance-related source, React finance pages, `NEXUS.Persistence/AppDbContext.cs`, `AppDbContextModelSnapshot.cs`, and payment migration sources are already modified or untracked. Those files are protected in-flight work and were not changed for this inventory.

No database was queried. The actual Development server/database identity, applied migration history, record counts, tenant/project balances, physical schema, and backup status are **not verified**. Migration files in the worktree do not prove that they were applied. No amount, record count, tenant, or historical state is inferred here.

## 3. Cross-record invariants for any future reconciliation

- A project ceiling is not an allocation total. An allocation is not an actual cost, commitment, payment obligation, or settlement.
- A recognized cost and an unreconciled commitment can both contribute to exposure only when the amount matched from commitment to cost is subtracted from remaining commitment.
- A payment obligation and its settlements report amount due and cash paid. They do not become cost or budget consumption automatically.
- An overdue amount is a subset of outstanding obligations, not an additional exposure.
- A published snapshot is a historical captured result; current source corrections do not mutate it.
- Program/Portfolio aggregation must start from a unique authorized project set and keep currencies separate unless an FX rule and source rates are approved.
- Unknown ownership, missing currency, conflicting status, or ambiguous linkage is a reconciliation exception. Do not fill it with a default or inferred value.
