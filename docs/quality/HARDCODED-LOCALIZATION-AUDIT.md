# Hardcoded Localization Audit — FOPX PM

**Date:** 2026-11-17
**Mode:** READ-ONLY AUDIT — no fixes applied, nothing migrated or deleted.
**Scope:** `apps/web-react` (React/Vite, the only supported frontend per ADR-009), `apps/api/src` (.NET 10 modular monolith), `packages/`, `plugins/`, `modules/` (legacy), `apps/api/tools`, `apps/api/tests`, `tests/load`.

---

## 1. Authoritative localization architecture (as found)

| Layer | Location | Mechanism |
|---|---|---|
| Frontend message catalogs | `apps/web-react/src/i18n/messages/en.json`, `ar.json` (~8,270 lines each) | `I18nProvider` / `useI18n().t(key, params)` in `src/i18n/messages.tsx`; EN fallback to key; `{param}` interpolation; RTL via `document.documentElement.dir` |
| API error localization | `apps/web-react/src/api/api-error-localization.ts` + `src/api/client.ts` | Maps ProblemDetails `code` → `apiErrors.*` catalog keys; status→key fallback; regex-based field-message translation; English `detail` pass-through only when `isSafeServerMessage` |
| Formatting | `src/lib/formatting/{currency,date,number,regional}.ts` | `Intl.*` with runtime regional defaults (`RegionalDefaults` from API) |
| Branding | `apps/web-react/brand.json` via `src/lib/brand.ts` (`brandCopy(locale)`) | Centralized EN/AR brand copy |
| Backend error contract | `apps/api/src/NEXUS.Api/Middleware/ApiProblemDetails.cs`, `NEXUS.SharedKernel/Error.cs` | `Error(code, message, status, fieldName, details)` → ProblemDetails `{code, detail, errors, details}`; stable UPPER_SNAKE codes; English `TitleForStatus`/`DetailForStatus` defaults |
| Backend bilingual data | Entity/catalog records carry `nameEn`/`nameAr`, `labelEn`/`labelAr`, `descriptionEn`/`descriptionAr` pairs; frontend selects via `locale === "ar" ? x.nameAr : x.nameEn` | Legitimate pattern — backend-owned bilingual business data |
| Notification convention | Concatenated `"English\n\nArabic"` (or `\n`) payloads split client-side by `src/lib/notification-content.ts` for a hardcoded type list; some publishers resolve recipient `regional.defaultLanguage` and emit single-locale text | Fragile hybrid — see findings N-01/N-02 |

**Orphaned parallel catalog:** `packages/localization/messages/{en,ar}.json` (899 lines each) is a small duplicate message package not referenced by `apps/web-react` (not in its `package.json`).

### B. Frontend — legitimate (not violations)

- `src/i18n/messages/{en,ar}.json` — authoritative catalogs.
- `locale === "ar" ? x.nameAr : x.nameEn` patterns selecting **backend-provided** bilingual fields (statuses, units, categories, permissions, workflow states) — legitimate data-driven localization, e.g. `WorkItemPages.tsx`, `OrganizationPage.tsx`, `permission-labels.ts`, `project-lifecycle.ts`.
- `dir={locale === "ar" ? "rtl" : "ltr"}` — technical.
- Enum union types (`"Pending" | "Completed"`, `"View" | "Action"`), API DTO types, CSS/status-tone maps (`status-presentation.ts`), technical constants (`nexus-*` storage keys, `Ctrl K`), `brand.json`.
- `lib/audit-format.ts`, `lib/enums.ts` — map codes→i18n keys (correct pattern).
- Test files under `src/test/` — fixtures, excluded per skill rules.
- `cost-utilization-export.ts`, `planning-export.ts`, `ProjectsListPage` export — correctly use `t()` for headers/labels.

## 4. Consolidation strategy (recommendation — not implemented)

1. **Single frontend catalog authority.** Extend `en.json`/`ar.json` with: `apiErrors.fieldLabels.*` (absorbs F-01), `common.dateInput.*` (F-08), `account.about.*` (F-09), `dashboard.pov.*` + view-name templates (F-14), `directoryIntegration.actions.*`/`classifications.*`/`statuses.*` (F-13), `workflows.state badges` reuse (F-10). Delete `DateInput.LABELS`, `AboutPages` literals, POV literals, and the `project-status-report-export` dictionaries (F-04) in favor of the existing `localizedMessage()` lookup — it already reads the same catalogs.
2. **Kill the regex-message-matching layer.** Replace `api-error-localization`'s English-regex field parser and `planning-import-messages`' 30 exact-string matchers with backend-owned stable `code`s (+ `details` parameters). The `DOCUMENT_TEMPLATE_FILE_TYPE_MISMATCH` code+details pattern is the model to generalize.
3. **Backend message catalog.** Introduce a backend-owned bilingual resource (resx or JSON satellite) for: `Error.*` business messages (prioritize the ~2,856 call sites by user exposure — start with validation/business errors in ProjectManagement, Meetings, Documents, Finance workflows), notification titles/bodies (unify on the `RiskActionFollowUpProcessor` per-recipient-locale pattern or structured `{en,ar}` fields), ProblemDetails titles, and the document-compliance findings (B-02/B-03). Pair every message with a stable code so the frontend never parses English.
4. **Notification payload contract.** Replace `"EN\n\nAR"` concatenation + `notification-content.ts` allowlist with structured fields or per-type template keys resolved by recipient `regional.defaultLanguage`; cover `ProjectStatusReport`, handover, payment-due, and AI types.
5. **Data fixes.** Correct the `SeedDataProvider` mojibake (B-01) and audit already-seeded rows; fix the `"?????"` fallback (F-05); QA `PermissionCatalog` Arabic descriptions.
6. **Formatting.** Route all `Intl` calls through the formatting utils honoring `RegionalDefaults`; remove hardcoded `"ar-EG"`/`"en-US"`/`"en-GB"` tags (F-24).
7. **Hygiene.** Remove or adopt `packages/localization`; dedupe `brandCopy` (F-25); align Swagger title with `brand.json`; confirm `modules/projects` is dead code.
