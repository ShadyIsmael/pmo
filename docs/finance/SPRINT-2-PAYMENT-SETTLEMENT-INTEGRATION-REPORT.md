# Sprint 2 Task 03 — Payment Settlement & Actual Paid Integration

**Status:** Task 03 complete. Implementation and migration created. Build passed.  
**Date:** 2026-11-22  
**Scope:** Task 03 only. Task 04 was not started.

## 1. Executive summary

Task 03 connects approved installment-based Payment Requests with confirmed Payment Settlements so that Actual Paid, Outstanding Payable, installment balances, and Planned Payment payment status derive only from authoritative settlement records.

Changes:

- `PaymentSettlement` gains `PlannedPaymentInstallmentId` (nullable FK to `PlannedPaymentInstallments`) and a navigation property, so each request settlement directly references the installment it pays.
- `PlannedPaymentInstallment` gains a persisted `ActualPaid` field and a computed `OutstandingBalance` (`Amount - ActualPaid`), both derived from settlement records.
- `PlannedPayment` gains a computed `PaymentStatus` ("Not Paid", "Partially Paid", "Fully Paid") derived from confirmed settlement amounts across its installments.
- `RecordSettlementAsync` now sets `PlannedPaymentInstallmentId` on the new `PaymentSettlement` and increments the target installment's `ActualPaid` within the same serializable transaction.
- `LoadSettledByInstallmentAsync` uses the direct settlement→installment FK for new settlements, falling back to the indirect payment-request→detail→installment path for settlements recorded before this change; double-counting is prevented by skipping direct-FK settlements in the indirect path.
- `ActualPaidSettlementCalculator.SettlementFact` now carries `PlannedPaymentInstallmentId` so obligation and request settlement facts can be traced to their installment.
- `PlannedPaymentInstallmentDto` adds `ActualPaid` and `OutstandingBalance`. `PlannedPaymentDto` adds `PaymentStatus`.
- Additive migration `20261122110754_AddTask03PaymentSettlementInstallmentLinkage` adds `ActualPaid` to `PlannedPaymentInstallments`, `PlannedPaymentInstallmentId` to `PaymentSettlements` (with index and FK), and updates the model snapshot.

No existing permissions changed. No new permissions introduced. Existing role grants preserved.
